# ADR-009 — Preserve provider-qualified Pi tool call IDs

- Status: Accepted
- Date: 2026-08-12

## Context

Signals derives an agent command ID as `tool:<toolCallId>`. Pi 0.84.1 can supply an OpenAI provider-qualified tool call ID with this form:

```text
call_Z6LPv0kJq22rXsNP67ojPhlg|fc_068d35c2414bddfc016a7c4fb7e8f4819881a1ba59d0364046
```

The existing command ID validator accepted only ASCII letters, digits, `.`, `_`, `:`, and `-` after the actor prefix. It rejected the `|` separator. This caused a valid host tool call to fail before persistence.

The extension execute signature defines `toolCallId` as a host string. The host can therefore use provider-qualified punctuation that is narrower than arbitrary text but wider than the original schema-era pattern.

## Decision

Signals preserves the exact host value in `tool:<toolCallId>`. It does not hash, encode, normalize, or truncate the value.

A `tool:` command suffix accepts only ASCII letters, digits, `.`, `_`, `:`, `-`, and `|`. The `ui:` and `system:` suffix sets remain unchanged and do not accept `|`. The existing 240-character suffix bound and 256-character total bound remain. The validator still requires an exact `tool:`, `ui:`, or `system:` prefix.

The event codec uses this shared validator. It also continues to enforce the actor-to-prefix rule. Whitespace, controls, arbitrary Unicode, slash, backslash, quotes, `$`, `;`, `&`, and other punctuation remain invalid.

## Consequences

Provider-qualified Pi tool calls retain stable command identity across append, replay, and retries. An identical retry returns the prior result without another append. A different semantic command with the same host call ID remains a conflict.

The sealed specification schema is not edited. The source-owned validator and codec define the compatibility adapter for actual Pi 0.84.1 host IDs.
